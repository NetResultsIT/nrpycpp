# nrPyCpp

A small Qt library to call Python functions from C++. It was written for VDK, so that packet parsers,
codecs and similar pieces can be prototyped in Python and called from the C++ code without rebuilding it.

```cpp
#include "PyRunnerQt.h"

PyRunnerQt runner("/path/to/codec.py", QStringList());
PyFunctionCallResult r = runner.syncCallFunction("decode", QVariantList() << packet);
if (r.error)
    qWarning().noquote() << r.errorMessage;   // includes the python traceback
else
    QByteArray payload = r.returnValue.toByteArray();
```

- Desktop only: macOS (universal arm64 + x86_64), Linux x86_64, Windows x64.
- Qt 6 (tested with 6.8.6; Qt 5 should still build but is not tested any more), C++17, qmake.
- Python 3.13, embedded: the application ships its own relocatable CPython (about 10 MB compressed),
  published on artifactory as `deps/python`. No python installation is needed or used on the target machine.
- Optional user virtual environment, for third party packages (`scapy`, `construct`, `crcmod`...).

## Quick start (development build)

```sh
# 1. the python runtime: download it from artifactory (deps/python), or prepare it locally
python3 tools/prepare_python_runtime.py prepare --platform macos --out build/python
tar xzf build/python/upload/deps/python/release/3.13.18/macos/python-3.13.18-macos.tgz -C build/python

# 2. build the library and run the tests against it
NRPYCPP_PYTHON_ROOT=$PWD/build/python/python QMAKE=~/Qt/6.8.6/macos/bin/qmake tests/run_tests.sh
```

The library, its public headers and the python shared library end up in `lib/last_build/`.
On Windows use `tests\run_tests.ps1` (see [docs/BUILDING.md](docs/BUILDING.md)).
